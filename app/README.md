# BookIt native app (android + ios)

One Expo + React Native codebase (Expo SDK 57, Expo Router). `ios/` and
`android/` are generated by `expo prebuild` and committed, so that Xcode,
Gradle and Appium have real native projects. Don't hand-edit them.
Change `app.json`, then regenerate with `npm run prebuild`. Because the
native folders are committed, `expo-doctor`'s "app config fields not synced"
check is disabled in `package.json`. Running prebuild after every
`app.json` change is what keeps them in sync.

## Prerequisites

- Node 22
- **android:** Android Studio, an Android SDK, and an emulator (API 34+)
- **ios:** macOS, Xcode 16+, CocoaPods, and an iOS simulator

## Run

```sh
cd app
npm ci
docker compose up -d        # from the repo root: API on :8000
npm run android             # expo run:android (builds android/ and installs on the emulator)
npm run ios                 # expo run:ios (pod install, builds ios/, runs on the simulator)
```

The app finds the API on its own:
- android uses `http://10.0.2.2:8000`, which is the emulator's alias for the host.
- ios uses `http://localhost:8000`.
- Set `EXPO_PUBLIC_API_URL` to use something else, e.g. a physical device
  on your LAN.

## Test hooks

| Hook | How |
|---|---|
| Test session | Deep link `bookit://login?testSession=<id>`, or build with `EXPO_PUBLIC_TEST_SESSION=<id>` |
| Deep links | `bookit://schedule?date=YYYY-MM-DD`, `bookit://classes/<class_id>`, `bookit://bookings` |
| Identifiers | `testID` values from `docs/design/testids.md` (iOS: accessibility id; Android: resource-id) |

Android deep link from a shell:
`adb shell am start -W -a android.intent.action.VIEW -d "bookit://login?testSession=w1" com.bookit.sut`

iOS deep link from a shell: `xcrun simctl openurl booted "bookit://login?testSession=w1"`

## Scripts

| Script | What |
|---|---|
| `npm run gen:api` | Regenerate `src/api-schema.ts` from `docs/api/openapi.json` |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run prebuild` | Regenerate `ios/` and `android/` from `app.json` |
