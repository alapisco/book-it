# BookIt native app (android + ios)

One Expo + React Native codebase (Expo SDK 57, Expo Router) produces both
apps. Their bottom tabs are Schedule, Week, Bookings and Policies.

`ios/` and `android/` are generated by `expo prebuild` and committed, so
that Xcode, Gradle and Appium have real native projects.
- Don't hand-edit them. Change `app.json`, then regenerate with
  `npm run prebuild`.
- Because the native folders are committed, `expo-doctor`'s "app config
  fields not synced" check is disabled in `package.json`. Running prebuild
  after every `app.json` change is what keeps them in sync.

## 1. Machine setup (once)

| Need | android | ios |
|---|---|---|
| OS | Linux, macOS or Windows | macOS only |
| Node | 22 | 22 |
| Java | **Full JDK 17** (must include `javac`, not only a runtime) | — |
| SDK | Android Studio → SDK Manager: SDK Platform 36, Build-Tools, Platform-Tools, Emulator, Command-line Tools; one emulator (AVD) with API 34+ | Xcode 16+ with an iOS simulator runtime, and CocoaPods (`brew install cocoapods`) |

Machine-specific settings (SDK and JDK paths) belong in **your shell
profile or your user-level Gradle config, never in the repo**. The
committed files stay portable, and `npm run prebuild`, which deletes and
recreates `android/`, can't wipe your setup.

### android: environment variables

Add these to `~/.bashrc` or `~/.zshrc`, then open a new terminal.

```sh
# Android SDK
# Linux default: ~/Android/Sdk    macOS default: ~/Library/Android/sdk
export ANDROID_HOME="$HOME/Android/Sdk"
export PATH="$PATH:$ANDROID_HOME/emulator:$ANDROID_HOME/platform-tools"

# JDK 17 for Gradle, React Native and Expo
export JAVA_HOME=/usr/lib/jvm/temurin-17-jdk   # adjust to your JDK 17 path (see below)
export PATH="$JAVA_HOME/bin:$PATH"
```

Then pin Gradle to the same JDK in your **user-level** Gradle file,
`~/.gradle/gradle.properties`. Create it if it's missing; it isn't the
file inside `app/android/`.

```properties
org.gradle.java.home=/usr/lib/jvm/temurin-17-jdk
```

This matters when several Java versions are installed. Without it, Gradle
may auto-detect a newer runtime-only Java and fail (see
[Troubleshooting](#6-troubleshooting)).

**Finding or installing JDK 17:**
- **Fedora/RHEL:** `sudo dnf install java-17-openjdk-devel` (the `-devel`
  package contains `javac`), or install Temurin 17 from the
  [Adoptium repo](https://adoptium.net/installation/linux/).
  Installed JDKs are under `/usr/lib/jvm/`.
- **Ubuntu/Debian:** `sudo apt install openjdk-17-jdk`.
- **macOS:** `brew install --cask zulu@17`. Then
  `export JAVA_HOME=$(/usr/libexec/java_home -v 17)`.
- **Any OS:** [SDKMAN](https://sdkman.io): `sdk install java 17.0.13-tem`.

> **About `local.properties`.** If `ANDROID_HOME` isn't set, Gradle stops
> with *"SDK location not found. Define a valid SDK location with an
> ANDROID_HOME environment variable or by setting the sdk.dir path in your
> project's local properties file"*. Creating
> `app/android/local.properties` with `sdk.dir=/home/you/Android/Sdk` also
> works, and the file is git-ignored. But `npm run prebuild` deletes it
> along with the rest of `android/`, so prefer `ANDROID_HOME`.

### ios: one-time steps

```sh
xcode-select --install                       # command-line tools
sudo xcodebuild -license accept
xcrun simctl list devices available          # at least one iPhone simulator
```

### Check your setup

```sh
node -v                  # v22.x
java -version            # 17.x
javac -version           # 17.x; if missing, you have a runtime, not a JDK
echo $ANDROID_HOME       # your SDK path
adb version              # proves platform-tools is on PATH
emulator -list-avds      # at least one AVD
xcodebuild -version      # macOS only
```

## 2. Run for development

```sh
docker compose up -d        # from the repo root: API on :8000, web on :5173
cd app
npm ci
npm run android             # build, install on the running emulator, start Metro
npm run ios                 # pod install, build, run on the simulator, start Metro
```

These are **Debug** builds. They load JavaScript from the Metro dev
server, so code changes appear without rebuilding, but the app only works
while Metro runs.

### Upgrading to M4

After pulling M4, run `npm install` in `app/` to add the new
`lucide-react-native` dependency. A JavaScript reload is enough; there is
no native rebuild. If Metro still can't resolve the icons, restart it
with `npx expo start --clear`.

## 3. Build installable files for automation

For Appium and CI, build **Release** artifacts. They contain the
JavaScript bundle and run without Metro. Settings from `.env.local` (see
[Configuration](#4-configuration)) are baked in at build time.

| Command (in `app/`) | Output | Use |
|---|---|---|
| `npm run build:android` | `android/app/build/outputs/apk/release/app-release.apk` | Appium on an emulator; self-contained |
| `npm run build:android:debug` | `android/app/build/outputs/apk/debug/app-debug.apk` | Manual debugging only; needs Metro (`npx expo start`) and `adb reverse tcp:8081 tcp:8081` |
| `npm run build:ios` (macOS) | `ios/build/Build/Products/Release-iphonesimulator/BookIt.app` | Appium on a simulator; self-contained |

- **Signing.** The release APK is signed with the debug keystore that ships
  in the project, which is fine for emulators. It isn't meant for Play
  Store upload.
- **Simulator only.** The iOS `.app` runs only on simulators. A physical
  iPhone needs a signed `.ipa`, which is out of scope here.
- **Not committed.** Both output folders are git-ignored.

Install by hand:

```sh
adb install -r android/app/build/outputs/apk/release/app-release.apk
xcrun simctl install booted ios/build/Build/Products/Release-iphonesimulator/BookIt.app
```

Appium capabilities:

| Capability | android | ios |
|---|---|---|
| `platformName` | `Android` | `iOS` |
| `appium:automationName` | `UiAutomator2` | `XCUITest` |
| `appium:app` | absolute path to `app-release.apk` | absolute path to `BookIt.app` |
| `appium:appPackage` / `appium:bundleId` | `com.bookit.sut` | `com.bookit.sut` |

At run time the app still needs the backend: `docker compose up` from the
repo root.

## 4. Configuration

Defaults work on a local emulator or simulator with no configuration. To
override them, copy [`.env.example`](.env.example) to `.env.local`
(git-ignored) and uncomment what you need:

| Variable | Default | When to set it |
|---|---|---|
| `EXPO_PUBLIC_API_URL` | android `http://10.0.2.2:8000`, ios `http://localhost:8000` | Physical device, or API elsewhere |
| `EXPO_PUBLIC_WEB_URL` | android `http://10.0.2.2:5173`, ios `http://localhost:5173` | Same, for the Policies webview |
| `EXPO_PUBLIC_TEST_SESSION` | none | Pin a whole build to one test session |

`10.0.2.2` is the Android emulator's alias for your machine. Expo inlines
these values when it bundles, so rebuild after changing them.

The Policies tab embeds the web app's `/policies` page, so the web app
must be running. The webview is debuggable, so Appium can switch to its
`WEBVIEW_*` context and use the wap identifiers.

## 5. Test hooks

| Hook | How |
|---|---|
| Test session | Deep link `bookit://login?testSession=<id>`, or `EXPO_PUBLIC_TEST_SESSION` |
| Deep links | `bookit://schedule?date=YYYY-MM-DD`, `bookit://classes/<class_id>`, `bookit://bookings` |
| Identifiers | `testID` values from `docs/design/testids.md` (iOS: accessibility id; Android: resource-id) |

```sh
adb shell am start -W -a android.intent.action.VIEW -d "bookit://login?testSession=w1" com.bookit.sut
xcrun simctl openurl booted "bookit://login?testSession=w1"
```

**QR check-in demo:**
1. Log in and open a booked class whose check-in window is open (30
   minutes before the start until 15 minutes after). To get one, set the
   clock: `POST /test/clock {"now": "<start_at minus 10 minutes>"}`.
2. Tap "Show check-in code".
3. Play the gym's scanner from the repo root:
   `python3 scripts/simulate_scan.py <code> --studio <studio id> [--session <id>]`.
4. Within 2 seconds, the app shows "Checked in at HH:MM" (studio local time).

**Other scripts:**

| Script | What |
|---|---|
| `npm run gen:api` | Regenerate `src/api-schema.ts` from `docs/api/openapi.json` |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run prebuild` | Regenerate `ios/` and `android/` from `app.json` (deletes `android/local.properties`) |

## 6. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `Toolchain installation '/usr/lib/jvm/java-XX-openjdk' does not provide the required capabilities: [JAVA_COMPILER]` | Gradle picked a Java runtime without `javac` (on Fedora, the non-`-devel` package) | Install a full JDK 17, set `JAVA_HOME`, and add `org.gradle.java.home` to `~/.gradle/gradle.properties`. Then run `cd android && ./gradlew --stop` and rebuild |
| `SDK location not found` | `ANDROID_HOME` not set in this shell | Set it in your shell profile and open a new terminal |
| `adb: command not found` / `emulator: command not found` | `platform-tools` / `emulator` not on `PATH` | See the environment variables above |
| Red screen "Unable to load script" | A Debug build without Metro running | Use `npm run android`, or build Release with `npm run build:android` |
| "Could not reach the server." | Backend not running, or wrong URL on a physical device | `docker compose up`; on a device, set `EXPO_PUBLIC_API_URL` / `EXPO_PUBLIC_WEB_URL` to your machine's LAN IP |
| Problems Report with "deprecated" warnings | Deprecations inside the React Native and Expo Gradle plugins | Harmless; check the terminal for `BUILD SUCCESSFUL` |
| New native module missing after `git pull` | `react-native-webview` / `react-native-svg` need a native rebuild | `npm ci`, then rebuild (`npm run android` / `ios`, or `build:*`) |
